Relay vs Relay Fan-out

A relay moves data from one source plug to destination plug code. Fan-out keeps the same source run, but gives the workflow a list of destination contexts so it can deliver to several plugs in one run.

What Khotan does at run start

Resolve the flow

Khotan finds the registered relay on the source plug and keeps the configured to value. For fan-out, that value is an array of plug names.

Load source and destination vars

The source vars become ctx.vars. Each destination plug gets a separate entry in ctx.destinations and ctx.plugVarsByName.

Call the workflow or inline run handler

Khotan passes plain JSON context into the relay code. The relay code decides how to transform and send the data.

Finalize one Khotan run

The workflow returns counters and metadata. Khotan records the run once, even if the workflow delivered to several destinations.

Single relay and fan-out relay config

relay({
  name: "products-relay",
  to: "pollinate",
  resource: "products",
  workflow: productsRelayWorkflow,
});
relay({
  name: "products-relay",
  to: ["pollinate", "invoice-agent"],
  resource: "products",
  workflow: productsRelayWorkflow,
});

What the workflow receives

ctx.flow.to

The original destination config. It is a string for single relay and an array for fan-out.

ctx.flow.destinations

A lightweight list of destination refs: { name, plugName }.

ctx.destinations

Runtime destination contexts. Each entry includes vars, and profile/target when selected.

Fan-out workflow shape

async function forwardProducts(ctx: RelayContext) {
  "use step";

  const records = await readProductsFromSource(ctx.vars);

  for (const destination of ctx.destinations) {
    if (destination.name === "pollinate") {
      await sendToPollinate(records, destination.vars);
    }

    if (destination.name === "invoice-agent") {
      const invoices = productsToInvoiceDrafts(records);
      await sendToInvoiceAgent(invoices, destination.vars);
    }
  }

  return {
    extracted: records.length,
    transformed: records.length,
    created: records.length,
    metadata: {
      destinations: ctx.destinations.map((d) => d.name),
    },
  };
}

Important: fan-out does not automatically POST to every plug for you. Khotan resolves the destination list and injects destination vars. Your relay workflow still owns the transform, validation, API calls, batching, idempotency, and per-destination error handling.
